# v0.1.0 (2026-11-10, TestPyPI)

First usable version: read-only commands.

## Added

- Commands: `wekan whoami`, `wekan boards`, `wekan board`, `wekan card N`, `wekan config`. `--json` for scripts,
  `--ids` to show Wekan IDs, `--archived` to include archived cards and lists.
- Board selection: `--board/-b` (alias, ID or title, case-insensitive) > `WEKAN_BOARD` > a `.wekan` file in the
  current folder or a folder above it (`board = "alias or ID"`).
- Credentials: `--credentials` > `WEKAN_CREDENTIALS` > `~/.config/wekan/credentials`. Warns when the file is
  readable by others. Board and user aliases in `~/.config/wekan/config.toml`.
- Token cache in `~/.cache/wekan/token.json` (file 600, folder 700): one login per token (~90 days) instead of one per
  command. A refused cached token triggers exactly one new login.
- Every command reads the board export (one request): card numbers, lists with WIP limits, checklists, labels and
  usernames. Lists show `[count/limit hard|soft]`, and `FULL` when the limit is reached.
- Errors: one line on stderr with a distinct exit code. A timeout, or an auth failure that took over 25 s, is reported
  as "Wekan can't reach its database" (exit 6) instead of a login problem, and doesn't trigger a re-login loop.

- Project skeleton (PR #1): `pyproject.toml` (hatchling, `wekan` entry point, httpx + typer, dev extras pytest/black/ruff),
  `src/` layout, `python -m wekan_cli`.
- `wekan --version` and `wekan version`. Help output is plain text (no rich boxes), so agents read it cheaply.
- Error classes with distinct exit codes (`errors.py`); `main()` prints one stderr line per error, and hides the
  message and traceback of unexpected errors (they could hold a secret) unless `WEKAN_DEBUG=1`.
- Test harness: a fake Wekan on `httpx.MockTransport` with the real API's quirks, a made-up demo board fixture, and an
  isolated `HOME` for every test.
- Dev tools: `pyright` (strict) in the dev extras, configured in `[tool.pyright]`, so the terminal and VS Code's
  Pylance run the same check.
- Docs: README, CLAUDE.md, `docs/claude/` (architecture, conventions, testing).
